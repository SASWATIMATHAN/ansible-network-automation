# 📘 Lab 06 — Jinja2 Templates

## 🎯 Objective

The objective of Lab 06 is to introduce Jinja2 templates in Ansible network automation and demonstrate how a single template can generate device-specific Cisco IOS configuration dynamically.

This lab builds directly on Lab 05 — Variables.

The lab demonstrates:

- Jinja2 template syntax
- Ansible variables inside Jinja2 templates
- `{{ inventory_hostname }}` for device-specific configuration
- Dynamic configuration generation
- Ansible template rendering
- Cisco IOS configuration using `cisco.ios.ios_config`
- Verification using `cisco.ios.ios_command`
- Separation of configuration logic from device-specific data
- Multi-device automation across R1, R2, and R3

---

# 🧠 Lab Concept

In traditional network configuration, each router may require a separate configuration file.

With Jinja2 templates, one template can be reused for multiple devices.

The template contains variables such as:

    {{ inventory_hostname }}

Ansible automatically replaces this variable with the hostname of the target device.

Therefore:

    R1 → Managed by Ansible - R1
    R2 → Managed by Ansible - R2
    R3 → Managed by Ansible - R3

The same Jinja2 template is reused for all three routers.

# 🧩 Jinja2 Template

File:

    templates/router_config.j2

Template:

    ! ==========================================
    ! Generated by Ansible Jinja2 Template
    ! ==========================================

    interface FastEthernet0/0
     description Managed by Ansible - {{ inventory_hostname }}

    !
    ! End of generated configuration
    !

The important Jinja2 expression is:

    {{ inventory_hostname }}

This value is replaced dynamically by Ansible.

For example:

    R1 → {{ inventory_hostname }} = R1
    R2 → {{ inventory_hostname }} = R2
    R3 → {{ inventory_hostname }} = R3

# 🧠 Learning Outcomes

After completing this lab, the following concepts were demonstrated:

## 1. Jinja2 Templates

Jinja2 allows configuration templates to contain dynamic variables.

## 2. Variable Interpolation

Ansible variables can be inserted into configuration templates using:

    {{ variable }}

## 3. Device-Specific Configuration

The same template can generate different configurations for different devices.

Example:

    R1 → Managed by Ansible - R1
    R2 → Managed by Ansible - R2

Generated configuration can be deployed directly to Cisco IOS devices using:

    cisco.ios.ios_config

## 5. Separation of Data and Configuration Logic

The Jinja2 template separates reusable configuration logic from device-specific information.

This becomes especially useful as the network grows.
