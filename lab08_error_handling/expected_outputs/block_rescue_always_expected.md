LAB 08 — BLOCK / RESCUE / ALWAYS
EXPECTED OUTPUT

Objective:
Demonstrate Ansible error handling using block, rescue, and always.

Expected workflow:

1. The router reachability task should succeed.
2. The intentional failure task should report FAILED.
3. The remaining task inside the block should not execute.
4. Ansible should enter the rescue section.
5. The rescue message should confirm that the failure was handled.
6. Router status should be collected successfully during rescue.
7. The always section should execute.
8. The final error-handling message should be displayed.
9. The play recap should show rescued=1 for each router.
10. The final failed count should be 0 because the failure was handled by rescue.
11. No router configuration should be changed.

Expected result for each router:

R1:
ok=4
changed=0
unreachable=0
failed=0
skipped=0
rescued=1
ignored=0

R2:
ok=4
changed=0
unreachable=0
failed=0
skipped=0
rescued=1
ignored=0

R3:
ok=4
changed=0
unreachable=0
failed=0
skipped=0
rescued=1
ignored=0

Expected error-handling sequence:

BLOCK
  ↓
Task succeeds
  ↓
Controlled failure
  ↓
RESCUE
  ↓
Recovery/verification
  ↓
ALWAYS
  ↓
Completion

Important:
The intentional failure is generated by ansible.builtin.fail and does not modify the Cisco routers.
